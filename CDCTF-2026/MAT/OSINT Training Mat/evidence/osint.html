What is Open Source Intelligence?

Open source intelligence, or OSINT, is the practice of collecting, processing, and analyzing data from public sources to answer specific questions or assess risks. It does not mean open-source software; instead, it uses any information that anyone can legally view, read, or download.

Open Source Intelligence (OSINT) in a Capture The Flag (CTF) competition is a category of challenges focused on gathering, verifying, and analyzing publicly available data to find a hidden string or file called a "flag". It tests your web search skills, digital forensics, and investigative logic.

Common Sources of OSINT

  • Social media sites and chat apps
  • Public government files and court records
  • News articles and media broadcasts
  • Academic papers and books
  • Commercial databases and public registries

Common OSINT Challenge Types

  • Geolocation: Finding the exact spot where a photo was taken by looking at street signs, building shapes, shadows, or image metadata.
  • Username Tracking: Following a target username across social media, forums, or developer sites to uncover personal details or hidden posts.
  • Historical Data: Using web archives to find deleted pages, old website versions, or forgotten assets.
  • Database Traversal: Pivoting through one or more public security databases (vulnerability databases, device search engines, registries) by following clues from one record to the next.
  • People Tracing: Piecing together corporate or personal footprints left behind in public registries, press releases, or code repositories.

Common OSINT Tools

You don't need to reinvent the wheel for most OSINT challenges — a handful of well-known tools cover the majority of common tasks. Here are a few worth getting familiar with before you dive into the challenges below.

  • OSINT Framework: Not a single tool, but a categorized directory of OSINT tools and resources organized by data type (usernames, emails, images, etc.) — a great starting point when you're not sure what to use.
  • Maltego: A graph-based tool for mapping relationships between people, domains, companies, and other entities, useful for visualizing how pieces of a people-tracing or corporate-footprint challenge connect.
  • theHarvester: Gathers emails, subdomains, hostnames, and related info for a target domain from public sources, handy for reconnaissance-style challenges.
  • Sherlock: Searches for a given username across a large number of social media and web platforms, useful for username-tracking challenges.
  • ExifTool: Reads and extracts metadata (including GPS coordinates, camera model, and timestamps) embedded in image and document files, often the very first step in a geolocation challenge.
  • Shodan: A search engine for internet-connected devices rather than web pages, useful when a challenge points you toward a specific exposed device or service.
  • Wayback Machine: Lets you view archived snapshots of web pages over time, essential for historical-data challenges involving deleted or changed content.

A Note Before You Start

You won't need all of these tools for every challenge, and some challenges can be solved with nothing more than a careful web search. Treat this list as a toolbox to pull from, not a checklist to complete.

Example Database Traversal Challenge

Not every OSINT challenge stops at one source. Sometimes you need to pivot from one public database to another, using a clue found in the first to search the second. This is common with security research: a vague vulnerability description can lead you to a specific CVE entry, and that entry can lead you to the exact detail the challenge is asking for.

"Crimson Credit Union's vulnerability scanners flagged an issue in one of our IoT brokers running Moquette. The flaw in its pattern-based ACL rules implementation allows an attacker to bypass authentication checks using missing input neutralization."

Identify which public database holds records like this, find the specific CVE entry that matches the memo's description, then use the details in that entry to determine the exact firmware version it affects. The flag format is cdctf{CVE-ID}.
