What is Password Cracking?

Password cracking is the process of recovering a plaintext password from a hash — a scrambled, one-way representation of that password. In a CTF, you're usually handed a hash (or a file full of them) and asked to recover the original password to find a flag.

Cracking is almost always done offline: rather than repeatedly guessing a password against a live login form, you take the hash itself and run high volumes of guesses against it locally, checking each guess's hash against the target hash until you get a match.

Common Approaches

  • Dictionary attack: Trying every word in a wordlist (like rockyou.txt) as a candidate password.
  • Brute force: Trying every possible combination of characters up to a given length. Effective on short/simple passwords, but slow as length grows.
  • Rule-based attack: Taking a dictionary and mutating each word (capitalizing, adding numbers, swapping letters for symbols) to catch common human password habits.

Hashes and Hash Types

A hash is the output of a one-way function: feed in a password, and you get back a fixed-length string that (in theory) can't be reversed back into the original input. Password systems store this hash instead of the plaintext password, so cracking means guessing inputs and comparing their hashes to the target rather than "decrypting" anything.

Different hashing algorithms produce different output lengths and formats, which is often your first clue about what you're dealing with before you even start cracking.

Toolbox

  • hashcat: Widely considered the fastest password recovery tool available, using your GPU to test huge numbers of candidate passwords per second. See the official hashcat wiki for full documentation.
  • John the Ripper: A versatile, CPU-based password cracker known for automatic hash-format detection and a flexible rule engine.
  • Name-That-Hash: A command-line tool that analyzes a hash string and suggests what algorithm likely produced it.
  • hashes.com: An online hash lookup/decryption service — handy for quick lookups of previously-cracked hashes, though it's not a substitute for running your own cracking tool on novel hashes.
  • rockyou.txt: A large wordlist of real-world leaked passwords, commonly bundled with Kali Linux at /usr/share/wordlists/rockyou.txt.gz. It's the standard first wordlist to try in almost any CTF password cracking challenge.

Basic Hashcat Guide

A typical hashcat command looks like this:

hashcat -a <attack mode> -m <hash type> <path to hash file> <path to wordlist>

The hash file and wordlist always come after the flags, and in that order: hashes first, wordlist second.

Common Attack Modes (-a)

ModeNameDescription
0Straight / DictionaryTries each word in the wordlist once, as-is.
1CombinationCombines words from two wordlists together.
3Brute-force / MaskTries every combination of characters matching a defined pattern.
6 / 7HybridCombines a wordlist with a brute-force mask, appended or prepended.

Common Hash Modes (-m)

ModeHash Type
0MD5

1000NTLM

Putting it together, cracking a file of MD5 hashes with a straight dictionary attack against rockyou.txt looks like:

hashcat -a0 -m0 hashes.txt rockyou.txt

Before You Continue

That hash cracked quickly — MD5 is fast to compute, which cuts both ways: convenient for legitimate use, but also easy for an attacker (or a competitor) to brute-force or dictionary-attack at high speed. Not every hash you'll encounter is that short, though.
